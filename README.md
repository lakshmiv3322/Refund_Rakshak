# RefundRakshak 🛡️

**Autonomous Indian Payment Grievance Redressal Platform**

> Money debited but not received? Get it back.

RefundRakshak is a production-grade, multilingual AI platform engineered for Indian banking and UPI customers whose accounts have been debited following failed payment transactions, delayed merchant refunds, or ATM failures. It deterministically computes statutory compensation under verified Reserve Bank of India (RBI) circulars, drafts formal grievance notices, tracks escalation milestones, and executes communications only with explicit human authorization.

---

## Architecture Overview

RefundRakshak combines large language model intelligence with a deterministic legal rules engine and a strict human-in-the-loop approval pipeline:

```
[ User Input / Screenshot Evidence ]
                │
                ▼
[ Secret Redaction Engine ] ──▶ (Auto-purges PINs, OTPs, CVVs, Passwords)
                │
                ▼
[ Multi-Turn Gemini Agent Loop ] ──▶ Dynamic Structured Plan + Tool Execution
                │
                ▼
[ Deterministic Rules Engine ] ──▶ Verified RBI Circulars (data/verified_rules.json)
                │                  (T+1 P2P / T+5 P2M & ATM / ₹100 per day compensation)
                ▼
[ Human-in-the-Loop Outbox ] ──▶ Explicit User Authorization Required
                │
                ├──▶ Direct SMTP / Resend Email (with User as Reply-To)
                ├──▶ Native Mail Client (mailto:)
                ├──▶ Evidence Pack PDF Generation
                ├──▶ WhatsApp Web Share
                └──▶ Official Bank Portal / Helpline
```

### Core Architecture Components

1. **Express & TypeScript Backend (`server.ts`)**:
   - Manages state in local SQLite (`better-sqlite3`) with zero demo data pre-seeded.
   - Enforces same-origin CORS by default in production.
   - Restricts API rate limits on grievance submission and action approvals.
   - Serves Vite client assets statically in production from `dist/`.

2. **Deterministic Rules Engine (`server/rules-engine.ts`)**:
   - **Zero Legal Hallucination Policy**: Statutory turnaround times and compensation rates are never generated by LLMs. Every figure is resolved from `data/verified_rules.json` with an official URL and `last_checked_date`.
   - **UPI P2P (Item 4(a))**: T+1 calendar days turnaround; ₹100 per day delayed compensation.
   - **UPI P2M (Item 4(b))**: T+5 calendar days turnaround; ₹100 per day delayed compensation.
   - **ATM Non-Dispensation (Item 1(a))**: T+5 calendar days turnaround; ₹100 per day delayed compensation.
   - **Delayed Merchant Refunds (Item 4(c))**: T+5 calendar days turnaround; ₹100 per day delayed compensation.
   - **Wrong Recipient UPI**: Procedural bank recall guidance with explicit disclaimer that no statutory delay compensation applies.
   - **Unauthorized Transactions**: Immediate "Golden Hour" emergency checklist, zero customer liability protection citation under RBI Circular `DBR.No.Leg.BC.78/09.07.005/2017-18`, and zero compensation promise.

3. **Human-in-the-Loop Outbox (`server/agent.ts`, `server/tools.ts`)**:
   - No email or complaint package is ever transmitted without explicit human review and approval.
   - Senders can inspect exact facts, edit recipient addresses, or switch to alternative channels (copy text, open mail client, download PDF, share via WhatsApp, or access the bank's official portal).
   - In outbound dispatches, the customer's verified email is always set as the `reply-to` address.

4. **Multi-Channel Identity (`server/store.ts`)**:
   - Customers can sign in using passwordless email magic links or phone OTPs to access their cases across devices.
   - Full compliance with Digital Personal Data Protection (DPDP) principles: 90-day retention policy, "Export my case" (JSON), and "Delete my data" (irreversible purge).

5. **Autonomous SLA Scheduler (`server/scheduler.ts`)**:
   - Runs daily checks against stored scenario IDs (`scenario_id`).
   - Automatically computes accrued statutory compensation.
   - Drafts Nodal Officer escalation notices after 7 days without bank response.
   - Prepares official RBI Ombudsman filings (`cms.rbi.org.in`) once the statutory 30-day waiting period has elapsed and the bank complaint reference number is recorded.

## Configuration & Environment Variables

Create your local `.env` file based on `.env.example`:

```bash
cp .env.example .env
```

| Variable | Description | Default / Example |
| :--- | :--- | :--- |
| `PORT` | Web server listening port | `8000` (production) / `3000` (dev) |
| `NODE_ENV` | Runtime environment (`production` or `development`) | `production` |
| `GEMINI_API_KEY` | Google Gemini API key for structured planning & vision OCR | Required for LLM features |
| `GEMINI_MODEL` | Primary model name | `gemini-3.8-flash` |
| `GEMINI_FALLBACK_MODEL` | Fallback model name if primary is unavailable | `gemini-3.8-flash` |
| `B2B_API_KEY` | Required bearer token for `/api/b2b/*` routes | Random secure secret |
| `CORS_ORIGINS` | Comma-delimited list of allowed CORS origins | Same-origin only if blank |
| `RESEND_API_KEY` | Optional API key for Resend email dispatch | Optional |
| `SMTP_HOST` / `SMTP_PORT` | Optional SMTP configuration for email delivery | Optional |
| `SMTP_USER` / `SMTP_PASS` | Optional SMTP authentication credentials | Optional |
| `ENABLE_SIM_TIME` | Enables simulation clock for testing only when combined with `?dev=1` | `false` |

## Running with Docker

RefundRakshak includes a production-ready, minimal `Dockerfile` based on `node:22-slim`:

### Using Docker Compose
```bash
docker compose up --build -d
```

Verify service health:
```bash
curl http://localhost:8000/api/health
```

### Manual Docker Build
```bash
docker build -t refundrakshak:latest .
docker run -p 8000:8000 -e GEMINI_API_KEY="your-api-key" refundrakshak:latest
```

## Safety & Legal Disclaimer

- **"Potential compensation estimate, subject to verification."**
- RefundRakshak is a software copilot designed to assist users in tracking turnaround times and organizing financial grievances. It does not provide formal legal advice, representation, or a financial guarantee of recovery.
- **Zero Sensitive Credential Policy**: RefundRakshak never requests, stores, or transmits UPI PINs, bank passwords, debit card CVVs, or OTPs. All incoming text and attachments are automatically scanned and redacted prior to processing.
- For cyber frauds or unauthorized account breaches, immediately call the National Cyber Crime Helpline at **1930** and submit a complaint at [cybercrime.gov.in](https://cybercrime.gov.in).
